# 仓门扫描对账台设计

预约单以箱号为主键，声明订单、托盘、数量、月台、窗口、净重及容差。输入扫描流为 JSONL，每条有稳定事件身份、UTC 时间、箱号、动作和来源字段。文件哈希冻结来源；事件身份重复且内容不同进入冲突记录。

数据流：预约配置 → 来源文件 → 事件规范化 → 事件时间排序 → 装卸状态机与拆并箱谱系 → 数量、称重、月台核对 → 差异结算 → JSON/Markdown 交接报告。

合法装卸顺序是 `gate → unload → check → exit`。称重与拆并箱事件不推进此状态。错误码 `illegal_transition` 阻断交接；缺少阶段为 `missing_stage`。拆箱 `children` 与并箱 `parents` 的数量之和须等于事件声明数量，只有守恒的关系写入 `lineage`。数量差异区分 `shortage` 与 `overage`，缺重为 `missing_weight`，越容差为 `weight_mismatch`。月台或时间窗口不符是 `wrong_dock_or_window`。未知箱号保留 `unknown_box` 问题。

决策为 `accepted`、`pending` 或 `blocked`，复核放行后为 `released`。阻断问题不会因其他正常扫描被覆盖；缺少证据不会得到 accepted。每次重算追加新版决策与谱系记录并重建业务问题队列，旧 run 结论、来源和原始事件不可变。配置文件哈希冻结在数据库；修改预约单须使用新工作区。当前只处理单批次本地扫描，不与仓储系统或承运人联网。

## 复核签署链

待核（pending）结论可由授权复核员签署放行：签署绑定当次 run、规则版本、事件与谱系证据摘要及复核原因，写入 `signoff` 后触发重算，结论转为 `released`；业务问题记录保留，签署不删除 issue。治理策略由配置 `review.policy` 冻结：`single` 为一名授权复核员放行，`dual` 要求两名不同复核员分别签署；阻断类结论不允许签署。同一人对同一证据版本重复签署被拒绝；撤销只追加撤销标记，撤销后同一复核员可重新签署。证据摘要覆盖该单据的事件、拆并谱系与身份冲突状态：重算时三者任一变化，旧签署保留为历史（superseded）但不作用于新结论；无变化的重算不影响有效签署。报告导出逐笔签署链（active/revoked/superseded）、逐 run 决策历史与策略说明，可逐笔核对签署身份与绑定的证据版本。
