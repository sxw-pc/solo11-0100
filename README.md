# 仓门扫描对账台

纯本地证据采集与业务决策工具。输入为虚构 fixture，运行中不访问网络。Python 3.11+ 标准库为运行依赖，pytest 为测试依赖。

## 快速开始

`python -m pip install . --no-build-isolation --no-deps` 在本地安装已预装构建工具的环境中构建此项目；运行期无第三方依赖。

`python -m dockscan demo` 自动初始化临时工作区、导入 fixture、计算决策并打印报告路径。`python -m dockscan --help` 查看手动导入、复核及报告命令。`python -m pytest -q` 运行自动化测试。

## 数据流和约束

配置文件的 SHA-256 冻结到 `meta`；`source` 存每个输入文件的哈希；`event` 存逐行规范化记录和事件身份；`issue` 保存解析或业务问题；`decision` 按 run 追加保存规则版本、业务结论、证据摘要和引用的事件 ID，旧 run 结论不可覆盖；`signoff` 保存复核签署链，签署绑定当次 run、规则版本、事件/谱系证据摘要与复核原因，撤销只追加标记不删除。导入采用单个 SQLite 事务；同文件哈希重入不重复写，同事件身份但不同内容进入冲突队列。业务规则读取事件时间而非文件顺序；未知对象或缺证据不能自动视为正常。决策重算保持源事件不可变；出现新事件、身份冲突或拆并谱系变化时旧签署失效（保留为历史），新结论不沿用旧放行。复核策略由配置 `review.policy` 冻结：`single` 为一名授权复核员签署放行，`dual` 要求两名不同复核员分别签署；阻断类结论不允许签署放行，签署不删除差异 issue。

错误码见 `issue.code`，报告同时输出 JSON 和 Markdown。`fixtures` 中是确定性的全虚构数据。首版只支持单机、单批；配置一旦冻结，变化需新建工作区。细分业务边界与未来方向由项目生成提示词约束，首版没有预置未来功能。
